# RTX 3080: DARTF FAST test at home

This prepares the upstream W8A8 detector, fused detection/segmentation head,
lightweight tracker and frame pipeline. It tests a recorded video and saves
timings, track IDs and optionally an annotated MP4. The web UI also offers
FAST in its Webcam tab; the native DARTF entry uses FP16 tracking.

**Status update, 2026-09-22:** FAST has run on the home RTX 3080. After the
transport fix, repeated single-dog requests reached 6.35 fps in the UI. This is
a functional/transfer measurement, not handled-food tracking validation. See
[the measurement log](../../temp-devlog.md). The preparation notes below describe
the earlier 5070-only handoff and are retained for context.

The target is SM86 (RTX 3080, including the 10 GB and 12 GB variants). The setup
refuses to build or run these engines on the current SM120 RTX 5070. CUDA plugin
compilation can be checked here; actual SM86 engine execution must be tested at
home. At the original handoff there was no measured RTX 3080 result.

Checked on the 5070 PC: SM86 plugin compilation, all downloads, 22 unit tests,
CPU backbone/text/fused-head exports, ONNX validation and a one-block GPTQ smoke
test. Full GPTQ, INT8 graph rewriting, engine building and FAST inference still
needed to run at home at that handoff; see the status update above for later execution.

## At home

Install Git and Docker Desktop with the WSL2 Linux backend and NVIDIA GPU access.
Use an up-to-date NVIDIA Windows driver. This standalone test runs Python inside
Docker; the ordinary Windows perception environment is optional for this test.

Clone the prepared branch, or pull it if you already have this checkout:

```powershell
git clone --branch dartf https://github.com/samisan2007/relish-mr.git
cd relish-mr
```

For an existing checkout: `git switch dartf`, then `git pull --ff-only`.

Build the images (large downloads on the first run):

```powershell
powershell -ExecutionPolicy Bypass -File perception\dartf\rtx3080.ps1 -Action Image
```

Accept the model terms at [facebook/sam3](https://huggingface.co/facebook/sam3),
then log in with a Hugging Face read token. Paste it into the interactive prompt;
it is stored only in the ignored local cache, not in a command or Git.

```powershell
powershell -ExecutionPolicy Bypass -File perception\dartf\rtx3080.ps1 -Action Login
powershell -ExecutionPolicy Bypass -File perception\dartf\rtx3080.ps1 -Action Check
```

`Check` must print the RTX 3080 with compute capability `[8, 6]`. Close other
GPU inference runs before building or testing. Now build:

```powershell
powershell -ExecutionPolicy Bypass -File perception\dartf\rtx3080.ps1 -Action Build
```

Build downloads the pinned SAM3 weights and 19 COCO 2017 images, exports ONNX,
quantizes the backbone on the CPU, builds two local TensorRT engines and compares
the INT8 backbone with FP32 outputs on three held-out images. That comparison
catches gross numerical errors; it does not establish detection or tracking
accuracy. Setup is much slower than ordinary inference and needs substantial
CPU RAM and disk space. Rerun `Build` after an interruption; completed stages
are reused, while an interrupted stage starts again.

Record a short video with the Windows Camera app: one pen, then two, crossing,
rotation and brief occlusion. Close Camera after recording. Test the saved file:

```powershell
powershell -ExecutionPolicy Bypass -File perception\dartf\rtx3080.ps1 -Action Test -Video "C:\Videos\pens.mp4" -Prompt pen -Frames 300 -Render
```

Replace the video path with your file. Use one prompt only. `-Render` runs two
passes on the same first 300 frames: first without display/video encoding, then
with an annotated output. Omit `-Render` for the headless speed test alone.

Results appear in `perception/dartf-local/rtx3080/assets/runs/<timestamp>/`:

- `headless.json`: processing timing comparable in method to upstream's headless
  benchmark, though GPU and footage differ. Initialization is excluded.
- `rendered.json` and `annotated.mp4`: timing including upstream rendering and
  video encoding, plus the video to inspect. The MP4's playback rate is not
  inference FPS.
- `*-tracks.txt`: per-frame IDs and boxes in MOT format.
- `environment.json`: GPU, TensorRT version, source revision and prompt.

The launcher prints FPS computed from total wall time per processed frame.
Overlapped stage timings should not be added together or treated as isolated
kernel timings. Check the overlay for missed objects and identities moving
between pens; distinct ID totals alone do not establish tracking quality.

For a live webcam check on Windows, close Camera and run:

```powershell
perception\.venv\Scripts\python.exe perception\dartf\webcam.py pen --camera 0 --frames 300
```

The preview shows FAST track boxes and IDs over the current camera frame. Press
Q to stop. The camera runs at 640x480 and streams JPEG frames into the same
W8A8 FAST pipeline; its headless timing is saved under `runs/`.
The preview uses the latest camera frame, so boxes can lag moving objects.
Use the recorded-video `-Render` command above to inspect aligned masks.
In the existing web UI, select **DARTF FAST (W8A8 TensorRT)** in the Webcam tab
and press Start to see aligned masks and IDs. Stop releases its Docker worker.

## What is reproducible

- DART source: `16fada39054ac5058f6e7c1e8748cb9cc288f90c`, cloned inside the
  Docker image. FAST does not require a separate Windows DART checkout.
- SAM3 weights: HF revision `3c879f39826c281e95690f02c7821c4de09afae7`.
- CUTLASS v3.5.1; custom plugins compiled for SM86 with three GEMM stages and
  both the main and utility header paths.
- The same base Python/TensorRT container as the native backend, with ffmpeg
  and fonts added in a separate `relish-dartf:sm86` image.
- Full 32-block W8A8 backbone, 1008 px, one prompt, masks, lightweight tracking,
  fused head and pipelined frame processing. No smaller student model or dropped
  masks are substituted.

The build reuses upstream's shipped activation scales and regenerates GPTQ
weights and corrected biases using all 16 published calibration images. This
avoids the upstream FP32 calibration engine that exposes every intermediate
activation and is unsuitable for a small GPU. Export, graph rewrites,
quantization and tracking use the pinned upstream implementations.

Weights, calibration images, engines, login cache and results live under the
ignored `perception/dartf-local/rtx3080/`. Do not copy the 5070's `.plan` files.
Engines are tied to the GPU/runtime. Use `-WorkDir "D:\DARTF-3080"` on **every**
command if you want another disk. Use a fresh work directory after changing
export code, recipes, GPU or TensorRT; successful stage markers do not inspect
manual changes to generated files.

## If something fails

- Docker connection/GPU errors: start Docker Desktop, select Linux containers
  and check its WSL2 GPU setup; rerun `Check`.
- HF authorization errors: accept the model terms and rerun `Login` using the
  same work directory.
- Process killed / exit 137: check Docker/WSL's CPU RAM limit and available host
  RAM. Export and GPTQ run on the CPU and can need more memory than inference.
- A compiler or numerical verification error: keep the error and stop before
  trusting speed results. The launcher propagates failures instead of switching
  to another model.

For comparison, keep the same source clip for SAM3/native DARTF and FAST. The
upstream ~30 fps figure is an RTX 4090 result, not a target guaranteed on a 3080.
See the [upstream recipe and benchmark](https://github.com/mkturkcan/DART/blob/16fada39054ac5058f6e7c1e8748cb9cc288f90c/dartf/README.md).
